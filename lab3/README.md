# Places: погода и интересные места

Настольное приложение на Go с графическим интерфейсом. Пользователь вводит название места, выбирает нужную локацию из списка и получает:

- текущую погоду в этой точке;
- список интересных мест в радиусе 1000 м: название, расстояние, описание и фотографию.

## Возможности

- **Поиск локаций.** По введённому тексту показывается до 5 вариантов в виде `1. Красная площадь, Москва [tourism.attraction]` (номер, название, тип).
- **Погода.** Описание, температура (°C), «ощущается как» (°C), влажность (%), давление (мм рт. ст.), скорость ветра (м/с).
- **Интересные места.** Категория `tourism.sights` в радиусе 1000 м, до 10 штук. Описание и фото берутся из Википедии, при их отсутствии из Geoapify, а если и там нет, описание формируется по шаблону.
- **Асинхронность.** Все сетевые запросы выполняются в фоне и не блокируют интерфейс. Запросы по разным местам идут параллельно.
- **Защита от устаревших ответов.** Если пользователь запустил новый поиск или выбрал другую локацию, ответ на предыдущий запрос игнорируется.

## Используемые сервисы

| Сервис | Для чего |
|---|---|
| [Geoapify](https://www.geoapify.com/) | геокодинг, поиск мест, детали места |
| [OpenWeatherMap](https://openweathermap.org/api) | текущая погода |
| Русская Википедия (MediaWiki API) | описание и миниатюра места |
| Wikimedia Commons | запасной источник картинки |

## Требования

- Go 1.24 или новее (этого требует библиотека gofetch).
- Компилятор C (gcc/clang): библиотека `github.com/andlabs/ui` использует cgo.
- Linux: пакеты разработки GTK 3, например `sudo apt install libgtk-3-dev`.
- Windows: MinGW-w64 (gcc в `PATH`).
- macOS: Xcode Command Line Tools.
- Ключи API: Geoapify и OpenWeatherMap (бесплатных тарифов достаточно).

## Установка и запуск

```bash
go mod tidy               # скачает зависимости и создаст go.sum
go build -o app .
```

Ключи передаются через переменные окружения.

Linux / macOS:

```bash
export GEOAPIFY_KEY=ваш_ключ_geoapify
export OPENWEATHER_KEY=ваш_ключ_openweather
./app
```

Windows (PowerShell):

```powershell
$env:GEOAPIFY_KEY="ваш_ключ_geoapify"
$env:OPENWEATHER_KEY="ваш_ключ_openweather"
.\app.exe
```

Если одна из переменных не задана, программа выведет подсказку и завершится.

## Как пользоваться

1. Введите название (например, «Красная площадь» или «Цветной проезд») и нажмите **Найти**.
2. Выберите нужный вариант в выпадающем списке.
3. В блоке «Погода» появится текущая погода, а в таблице ниже интересные места рядом.

## Архитектура асинхронности

### HTTP-слой

Запросы выполняет асинхронная HTTP-библиотека [gofetch](https://github.com/jzx17/gofetch) (v0.1.0): её метод `Client.GetAsync` сразу возвращает канал завершения. Приложение не вызывает `http.Client.Do` и не строит запросы на блокирующем клиенте. Поверх библиотеки в `httpclient.go` написан тонкий адаптер `AsyncClient` с интерфейсом:

- `GetAsync(ctx, url, callback)`: возвращается немедленно, результат приходит в callback;
- `Get(ctx, url) *Future[[]byte]`: то же в виде Future;
- `getJSON[T]` и `getImage`: разбор JSON и декодирование картинки, тоже возвращают Future сразу.

Адаптер добавляет то, чего нет в библиотеке:

- ограничивает число одновременных запросов (6);
- проверяет статус ответа (не 200 — ошибка с кодом) и ограничивает размер тела (5 МБ);
- принимает `context.Context`, поэтому при новом поиске запросы предыдущего отменяются;
- вырезает ключи API из текста ошибок, которые показываются в окне.

Внутри gofetch для запроса используется горутина и стандартный транспорт `net/http`, то есть это асинхронный интерфейс HTTP-библиотеки, а не собственный event-loop. Ожидание сокета не занимает поток ОС: его обслуживает netpoller среды выполнения Go.

### Future

Поверх HTTP-слоя работает собственный тип `Future[T]`. Его методы по смыслу соответствуют `CompletableFuture` из Java:

| Функция | Аналог в Java | Назначение |
|---|---|---|
| `Async` | `supplyAsync` | запустить функцию в горутине |
| `Then` | `thenApply` | преобразовать результат |
| `ThenCompose` | `thenCompose` | выполнить следующий асинхронный шаг |
| `ThenCombine` | `thenCombine` | объединить два независимых результата |
| `AllOf` | `allOf` | дождаться набора Future |
| `orElse` | `exceptionally` | подставить значение при ошибке |

Схема загрузки отчёта:

```
loadReport
├── fetchWeather ───────────────────────────────┐
└── fetchPlaceList → для каждого места:         ├─► ThenCombine → Report
      fetchPlace (параллельно)                  │
      Geoapify details → заголовок статьи       │
      → поиск по имени / по координатам         │
      → Википедия (описание, фото) → картинка ──┘
```

Изменять виджеты можно только из потока UI, поэтому результат из фоновой горутины передаётся через `ui.QueueMain`.

## Известные ограничения

- Радиус поиска задан константой `searchRadius` (1000 м), в интерфейсе он не меняется.
- Бесплатный тариф Geoapify ограничивает частоту запросов. Одновременных запросов не больше 6, но при ответе 429 описание строится из запасных источников.
- Фото поддерживаются в форматах JPEG и PNG.
- Ошибка запроса списка мест не показывается пользователю: он увидит «Интересных мест рядом не найдено».
