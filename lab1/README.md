# Multicast Peer Discovery

Приложение на Go, которое находит свои копии в локальной сети через multicast UDP и отслеживает моменты их появления и исчезновения.

## Как это работает

- При запуске каждый экземпляр генерирует случайный `ID` (16 hex-символов).
- Раз в `AnnounceSec` секунд отправляет в multicast-группу пакет вида `MAGIC="PING" | VER=1 | IDLEN | ID | IP`.
- Все экземпляры слушают одну и ту же группу и один и тот же порт.
- Получив пакет с чужим `ID`, добавляет/обновляет запись в таблице «живых копий» и печатает `[+] появилась новая копия`.
- Если от копии не было пакетов дольше `DeadTimeout`, при очередной чистке она удаляется и печатается `[-] копия исчезла`.

## Требования

- Go 1.22 или новее.
- Linux / macOS / Windows.
- Сеть, где разрешён multicast.

## Сборка

```bash
go mod tidy
go build -o mcast .
```

Если `go.mod` содержит `go 1.27.1` — заменить на свою версию, например `go 1.22`. `go mod tidy` заодно убирает лишние `// indirect` и подтягивает актуальные `golang.org/x/net` и `golang.org/x/sys`.

## Запуск

```bash
./mcast 224.0.0.1     # IPv4
./mcast ff02::1       # IPv6 (link-local, интерфейс подберётся автоматически)
```

Адрес multicast-группы передаётся единственным аргументом. Семейство (`udp4` / `udp6`) выбирается автоматически по адресу.

### Пример вывода при старте

```
Протокол: udp4, группа: 224.0.0.1, порт: 45678
Интерфейс: enp3s0
Мой IP: 192.168.1.42
Мой ID: 4b1c9e7a3f82d105

Слушаю группу. Ctrl+C — выход.
Живых копий: 0
```

## Тестирование

### Вариант 1. Несколько пользователей

1. Собрать бинарник в общем месте:
   ```bash
   go build -o /tmp/mcast .
   chmod +x /tmp/mcast
   ```

2. Создать двух пользователей (если их ещё нет):
   ```bash
   sudo useradd -m user1
   sudo useradd -m user2
   ```

3. Открыть два терминала и в каждом запустить бинарник от своего пользователя:
   ```bash
   sudo -u user1 /tmp/mcast 224.0.0.1
   ```
   ```bash
   sudo -u user2 /tmp/mcast 224.0.0.1
   ```

4. В первом терминале появится:
   ```
     [+] появилась новая копия: 192.168.1.42 (id=1a2b3c4d5e6f7081)
   ```
   Во втором — то же самое про первую копию.

5. Нажать `Ctrl+C` в одном из терминалов. Через `DeadTimeout` секунд во втором появится:
   ```
     [-] копия исчезла: 192.168.1.42
   ```

### Вариант 2. Два процесса от одного пользователя

```bash
./mcast 224.0.0.1     # терминал 1
./mcast 224.0.0.1     # терминал 2
```

Благодаря уникальному `ID` они всё равно увидят друг друга.

### Вариант 3. Две машины в одной подсети

Запустить бинарник на двух хостах в одной L2-сети. TTL/hop limit = 1 гарантирует, что пакеты не уйдут за пределы сегмента.

### Проверка трафика

```bash
sudo tcpdump -ni any udp port 45678
```

Каждые ~2 секунды (по умолчанию `AnnouncegitSec`) — небольшой UDP-пакет от каждого экземпляра.

Для IPv6:

```bash
sudo tcpdump -ni any ip6 and udp port 45678
```

## Настройки

Все параметры — в `config.go`, функция `DefaultConfig`:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `Port` | `45678` | UDP-порт для multicast-группы |
| `AnnounceSec` | `2s` | Как часто отправлять свой анонс |
| `DeadTimeout` | `5s` | Через сколько считать копию исчезнувшей |
| `SweepSec` | `1s` | Как часто запускать чистку мёртвых |
| `MaxPeers` | `64` | Верхняя граница размера таблицы |

## Остановка

`Ctrl+C` — корректное завершение: закрываются оба сокета, таблица не сохраняется, а `[+]`/`[-]` события в других копиях отобразятся через `DeadTimeout`.

## Структура проекта

```
app.go       — точка входа Run, оркестрация сокетов и сигналов
args.go      — разбор аргумента (multicast-адрес → family, group)
config.go    — параметры по умолчанию
loop.go      — основной цикл: анонсы, приём, чистка
main.go      — os.Exit(Run(os.Args))
network.go   — выбор интерфейса, создание recv/send сокетов
packet.go    — формат пакета и парсер
peers.go     — таблица «живых копий»
```
