Однопоточный неблокирующий SOCKS5-прокси-сервер

Реализация прокси-сервера стандарта SOCKS5 (RFC 1928) на языке Go поверх системных вызовов Linux (golang.org/x/sys/unix).

Архитектура и ключевые особенности

Один поток: привязка выполнения к одному системному потоку (runtime.LockOSThread()) и полное отсутствие пользовательских горутин.

Событийная модель (unix.Poll): единственный блокирующий системный вызов в программе — селектор unix.Poll. Все сокеты (слушающий TCP, клиентские TCP, исходящие TCP и общий UDP-сокет DNS) переведены в неблокирующий режим (O_NONBLOCK).

Контроль памяти и TCP Backpressure: на каждое соединение выделяется ровно два статических буфера по 32 КБ (c2u и u2c — всего 64 КБ на сессию). При заполнении буфера подписка на POLLIN снимается, задействуя встроенный контроль потока TCP.

Отсутствие холостых циклов: подписка на POLLIN выставляется только при наличии свободного места в буфере (Avail() > 0), а на POLLOUT — только при наличии данных на отправку (Len() > 0). В простое процесс спит в ядре ОС, потребляя 0% CPU.

Неблокирующий DNS-резолвер: один общий UDP-сокет для A-запросов (RFC 1035), адрес рекурсивного резолвера читается из /etc/resolv.conf, сопоставление ответов идёт по 16-битному ID транзакции.

Корректное завершение (TCP Half-Close): при получении EOF от одной из сторон и опустошении буфера выполняется unix.Shutdown(..., SHUT_WR), а полный unix.Close вызывается только после завершения передачи в обоих направлениях.

Структура проекта

main.go — точка входа, привязка к потоку ОС (runtime.LockOSThread), валидация аргумента порта и запуск сервера.

buffer.go — статический буфер фиксированного размера (32 КБ) без динамических аллокаций.

session.go — константы протокола SOCKS5 и структура клиентской сессии (Session).

dns.go — неблокирующий UDP DNS-резолвер (чтение /etc/resolv.conf, сборка и парсинг пакетов RFC 1035).

server.go — главный цикл событий (unix.Poll), конечный автомат SOCKS5, таймауты и двусторонняя пересылка данных.

Сборка и запуск

# Сборка бинарного файла
go build -buildvcs=false -o socks5-proxy .

# Запуск прокси на порту 1080
./socks5-proxy 1080


Способы тестирования

1. Базовая проверка через curl (DNS и IPv4)

Проверка резолвинга доменных имён на стороне прокси (ATYP = 0x03, схема socks5h://) и прямого подключения по IPv4 (ATYP = 0x01, схема socks5://):

# Запрос с резолвингом домена на стороне прокси
curl -v -x socks5h://127.0.0.1:1080 https://example.com

# Запрос с передачей готового IPv4-адреса
curl -v -x socks5://127.0.0.1:1080 http://93.184.216.34


2. Негативные тесты (проверка кодов ошибок SOCKS5)

Проверка корректного отклонения неподдерживаемых адресов, несуществующих доменов и закрытых портов:

# Отклонение IPv6 (должен вернуть код 0x08 — Address type not supported)
curl -v -x socks5://127.0.0.1:1080 http://[2606:2800:220:1:248:1893:25c8:1946]

# Несуществующий домен (NXDOMAIN / таймаут DNS -> код 0x04 — Host unreachable)
curl -v -x socks5h://127.0.0.1:1080 http://nonexistent.domain.invalid

# Закрытый порт на целевом хосте (код 0x05 — Connection refused)
curl -v -x socks5://127.0.0.1:1080 http://127.0.0.1:59999


3. Проверка отсутствия холостых циклов (0% CPU в простое)

Запустите прокси и проверьте нагрузку на процессор и поведение системных вызовов:

# В простое загрузка CPU должна составлять 0.0%
top -p $(pgrep socks5-proxy)

# Через strace процесс должен спать в poll(), а не крутить пустой цикл
strace -p $(pgrep socks5-proxy)


4. Проверка отсутствия утечек файловых дескрипторов и памяти

# Проверка числа потоков (NLWP) и резидентной памяти (RSS)
ps -o pid,nlwp,rss,comm -p $(pgrep socks5-proxy)

# После завершения всех клиентских запросов должны оставаться открытыми только stdin/stdout/stderr, listenFD и dnsFD
ls -l /proc/$(pgrep socks5-proxy)/fd


5. Проверка TCP Backpressure на больших файлах

Скачивание большого файла с искусственным ограничением скорости клиента (--limit-rate) позволяет убедиться, что потребление памяти (RSS) не растёт:

curl -x socks5h://127.0.0.1:1080 --limit-rate 100K -o /dev/null https://speed.hetzner.de/100MB.bin


6. Параллельная нагрузка в одном потоке

Запуск 20 одновременных запросов проверяет, что однопоточный цикл не блокируется на медленных соединениях:

seq 1 20 | xargs -n1 -P20 -I{} curl -s -o /dev/null -w "%{http_code}\n" -x socks5h://127.0.0.1:1080 https://example.com


7. Тестирование в реальном браузере (Google Chrome / Chromium)

Запуск изолированного окна браузера через прокси без изменения системных настроек:

google-chrome \
  --proxy-server="socks5://127.0.0.1:1080" \
  --host-resolver-rules="MAP * ~NOTFOUND , EXCLUDE 127.0.0.1" \
  --user-data-dir=/tmp/chrome-socks5-test
